# Product UI adoption audit — 10 September 2026

**Readiness: conditional adoption of established components; hold wider adoption of unreleased `main` until the release and interaction defects below are addressed.** Coworkers can install the real `0.9.0` archive and build representative screens on the inspected Next.js/React stack. That is useful evidence, but neither green library CI nor this fixture establishes that the coworker's application has been successfully upgraded. Current `main` adds useful APIs without a new release identity, and independent browser testing found failures in ordinary editing, selection and date-picker flows.

The first priorities are to give unreleased work accurate release notes and a distinct version, repair failed-save and selection behaviour, correct numeric parsing, keep date actions reachable, and replace misleading adoption examples. Keep the current release channel and gradual migration approach. A new distribution system or broad rewrite would not solve these problems.

### F03 — InlineEdit never clears saving after a rejected promise

**P1 · new · S/B/F · high confidence.** [src/components/primitives/inline-edit.tsx:54](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/inline-edit.tsx#L54).

`commit()` sets saving true and awaits `onSave`, with no rejection/finally path. The fixture catches the synthetic rejection in host code; the library still reports `saving=true` and leaves the supplied input disabled. The shipped story's direct promise-returning handlers also have no rejection handler. ErrorBoundary does not catch asynchronous event failures, as its own documentation correctly explains.

**Affected:** users editing cells/records when validation or persistence fails. **Remedy/acceptance:** clear pending state reliably, preserve an editable draft and a recoverable error path, define cancellation during save, and prevent duplicate commits while a request is pending. Test resolve, reject, retry, unchanged value and cancellation. Keep actual saving in the host. **Effort:** 1 day; **dependency:** agree the minimal error contract; **risk:** moderate behavioural change to a new unreleased API. Related focus work is F10.

### F04 — ColumnConfigPanel does not follow its current selection prop

**P2 · new · S/B/F · high confidence.** [src/components/primitives/column-config-panel.tsx:47](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/column-config-panel.tsx#L47).

The panel initialises private `order` and `visible` from `visibleKeys` once. Load a saved view changing parent keys from `['a']` to `['b']`, then open the existing panel: Alpha is still checked and Beta unchecked. Subsequent edits can emit the stale selection. This also needs review when the allowed `columns` list changes; dynamic permission enforcement remains the host's responsibility.

**Remedy/acceptance:** derive the committed selection/order from controlled props, or introduce a clearly documented draft/apply model that resynchronises at defined boundaries. Test external view switches, host rejection, reset, new/removed columns and locked columns. **Effort:** 0.5–1 day; **dependency:** choose controlled/draft semantics; **risk:** low-to-moderate new-API behaviour. Saved-view persistence should stay outside the library.

### F05 — Localised formatted inputs silently change numeric meaning

**P1 · new within an already known locale-support area · S/B/F · high confidence.** [src/components/primitives/formatted-input.tsx:15](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/formatted-input.tsx#L15), [src/components/primitives/formatted-input.tsx:91](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/formatted-input.tsx#L91).

`CurrencyInput locale="de-DE"` displays German formatting, but parsing strips everything except ASCII digits, dot and minus. Entering `1.234,56` emits **`1.23456`** and displays **`1,23`** on blur rather than 1,234.56 euros. PercentageInput and HoursInput share this parser. Source inspection also shows permissive stripping of arbitrary text rather than an explicit invalid-input state; those additional cases were not all browser-tested.

**Affected:** currency/hours/percentage users relying on the public locale option or pasting localised values. **Remedy/acceptance:** define a locale-aware parsing contract using the locale's separators, or explicitly restrict input and reject unsupported syntax without silently changing it. Test negatives, grouping, decimals, blanks, zero, invalid strings and precision; keep business rounding in the host. **Effort:** 1–2 days; **dependency:** parsing/error policy; **risk:** existing permissive inputs may change, so document migration. This does not require introducing a general i18n dependency.

### F06 — Combobox Enter can select an option hidden by loading/error state

**P1 · new · S/B/F · high confidence.** [src/components/primitives/combobox.tsx:89](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/combobox.tsx#L89), [src/components/primitives/combobox.tsx:181](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/combobox.tsx#L181).

Set `loading=true` while retaining the previous `options` array. No options are rendered, but Enter still looks up `filtered[activeIndex]` and calls selection. The fixture commits `stale` while the popup says loading. The error state uses the same rendering gate; its keyboard path shares this cause, though the explicit fixture used loading. The active-descendant can also refer to a non-rendered option in these states.

**Remedy/acceptance:** permit keyboard commitment only for an open, available, rendered and enabled option; clear/validate active state when results change. Test delayed results, loading/error transitions and changing option arrays. The host still owns request cancellation and stale-response handling. **Effort:** 0.5–1 day; **dependency:** none; **risk:** intentional behavioural correction, relevant to existing 0.6+ consumers.

### F07 — Combobox required and disabled props do not honour native form expectations

**P2 · new · S/B/F · high confidence.** [src/components/primitives/combobox.tsx:104](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/combobox.tsx#L104), [src/components/primitives/combobox.tsx:124](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/combobox.tsx#L124), [src/components/primitives/combobox.tsx:152](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/combobox.tsx#L152).

The required prop adds visible copy but does not validate a selected value or expose `aria-required`. Disabled only disables the visible input, leaving the hidden named input enabled. The fixture's empty required choice passes `form.checkValidity()`, and FormData includes the disabled control's retained value. Native Input/Select and the library's SearchSelect behave differently.

**Remedy/acceptance:** define validation against the selected value, expose the required state, and omit disabled values from submission. Verify single/multiple form data, empty required values and fieldset disabling. **Effort:** 0.5–1 day; **dependency:** F06 tests can share the fixture; **risk:** submissions relying on the accidental behaviour need a migration note. Host-side validation remains necessary.

### F08 — DatePicker sizes to viewport height instead of available popover space

**P1 · new · S/B/F · high confidence.** [src/styles/pickers.css:115](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/styles/pickers.css#L115), [src/components/primitives/date-picker.tsx:158](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/date-picker.tsx#L158).

This is a reachable form-flow/accessibility defect, not a credential or build issue. See [recorded geometry](2026-09-10-evidence/date-probe.json).

**Remedy/acceptance:** cap the panel against Radix's available height as well as viewport bounds, with a working scroll region/action layout. Test above/below placements, short windows, 320px widths, typed errors and zoom. **Effort:** 0.5–1 day; **dependency:** none; **risk:** low CSS/layout change, verify calendar and range panels. Invalid September 31 was rejected; October 4 committed without date-only conversion loss in the Melbourne-timezone test.

### F09 — Two sticky columns use offsets smaller than their rendered widths

**P2 · new · S/B/F · high confidence.** [src/components/data/data-table.tsx:49](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/data/data-table.tsx#L49), [src/components/data/data-table.tsx:63](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/data/data-table.tsx#L63), [src/components/data/data-table.tsx:164](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/data/data-table.tsx#L164).

**Remedy/acceptance:** choose one geometry model for widths and offsets, preserving or explicitly migrating the published ratio behaviour. ### F10 — New editing flows lose keyboard focus on close

**P2 · new · S/B/F · high confidence.** [src/components/primitives/inline-edit.tsx:41](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/inline-edit.tsx#L41), [src/components/primitives/inline-edit.tsx:65](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/inline-edit.tsx#L65), [src/components/primitives/drawer.tsx:8](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/drawer.tsx#L8), [src/components/primitives/drawer.tsx:35](https://github.com/tomrosscd/cd-product-ui/blob/78dd64e16d2aa7ae7e106687e11cb18bcc46ea04/src/components/primitives/drawer.tsx#L35).

In both fixture flows, focus ends on BODY after closing, even after waiting for dialog cleanup. **Remedy/acceptance:** restore InlineEdit's newly rendered trigger and support an explicit return target/autofocus callback for programmatic Drawer launches. ## Installation, upgrade and distribution recommendations

Use the **GitHub Release `.tgz` route** as the single supported coworker entry point. It worked as documented and has low maintenance overhead. Keep local vendored archives for projects that need that workflow, including committing a `*.tgz` ignore exception and lockfile. Building an unreleased revision must use a unique prerelease identity or clearly documented commit/hash until F01 is fixed. The README's “build unreleased” example currently clones the release tag; it should make that distinction explicit.

For an adopter: choose an exact supported Node/React version, follow the matching npm or pnpm instructions, import `styles.css` once at the root, apply `cui-root` to the intended area, and use ThemeProvider when React portals must follow a dark theme. The package does not supply fonts, route handling, persistence, authentication or business calculations. Missing `styles.css` or scope can produce unstyled/partially styled UI without a diagnostic; a short first-screen troubleshooting recipe is cheaper than a runtime warning framework.

Install charts only through `@convert/product-ui/charts`, with the documented optional Recharts/react-is peers. Fresh core fixtures did not install those chart peers; React/react-dom resolved to 19.2.8. Fonts fell back locally without external fetches. Assets are not automatically hosted: the existing 0.3 guide correctly says to copy selected assets or use supported bundler imports.

Upgrade one area at a time: styles/build smoke check, tokens/layout, content/control composition, then navigation. Retain local primitives while migration is incomplete. Review changes from **every intervening release**, especially overflow Progress behaviour, sidebar visibility and collapse controls, negative badges and table sizing. Roll back by restoring the dependency/archive/lockfile commit. Record consumer revision, installed archive hash, stack, scope and owner-confirmed verification in CONSUMERS; do not label a separate fixture pass as an application upgrade.

Registry copies transfer maintenance responsibility to the adopter, while a package keeps shared implementation centrally versioned. The retired registry should not be offered as an escape route for current package defects. No new hosting channel, motion library or broad tooling dependency is recommended.
