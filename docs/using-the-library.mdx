# Using the library

Install Product UI as a package and pin the version. Copying a code sample out of Storybook gives you a snapshot, not a component that improves when the library does.

Use the [installation guide](https://github.com/tomrosscd/cd-product-ui#install-the-library) for the released archive and upgrade instructions.

## Install

Each release attaches a built archive. Install it by URL, replacing both version numbers with the release you want:

```sh
pnpm add --save-exact https://github.com/tomrosscd/cd-product-ui/releases/download/VERSION_TAG/convert-product-ui-VERSION.tgz
```

The URL identifies a release. Commit `package.json` and the lockfile to retain its integrity hash. Release policy forbids replacing archives.

To reproduce a tagged release, build its archive outside your application's folder:

```sh
git clone --branch VERSION_TAG --depth 1 https://github.com/tomrosscd/cd-product-ui.git convert-product-ui
cd convert-product-ui
pnpm install --frozen-lockfile
pnpm pack --pack-destination artifacts
```

Copy the archive into a `vendor` folder in your application, then install it from there:

```sh
pnpm add --save-exact ./vendor/convert-product-ui-VERSION.tgz
```

Commit the archive and your lockfile alongside your application. Keep the relative path short, because deeply nested folders can hit package-manager path limits.

The archive holds the React components, type declarations, tokens and compiled CSS. You do not need to fork the repository. The package's `private: true` field prevents accidental publication to a registry and does not affect this install.

## Use it with React

Import the stylesheet once at your application root:

```tsx
import '@convert/product-ui/styles.css'
import { Card, StyledSelect } from '@convert/product-ui'

export function ProjectSummary() {
  return (
    <Card heading="Projects">
      <StyledSelect
        label="Project view"
        defaultValue="all"
        options={[
          { value: 'all', label: 'All projects' },
          { value: 'active', label: 'Active projects' },
        ]}
      />
    </Card>
  )
}
```

React is a peer dependency, so your application owns its React installation. This release targets React 19.2.

In Next.js, add `'use client'` to your own components that hold state or pass event handlers. Library modules that need a client boundary already declare one.

You do not need Next.js or Tailwind to use these components.

## Use the tokens without React

Import `@convert/product-ui/tokens.css` for the foundations, or `styles.css` for the foundations plus the component classes. For typed token data in JavaScript, import from `@convert/product-ui/tokens`.

The `examples/html` folder shows a styled card and native select with no React.

CSS gives you appearance only. Drawer behaviour, focus management and keyboard handling live in the React components, so another framework has to supply its own.

## Fonts and host styles

Your application loads its own licensed Roobert files, with Geist as the fallback. The package contains no font files.

For local Storybook, put font files in the ignored `local-fonts` folder. Storybook runs without them and falls back. Confirm distribution rights before publishing a Storybook build that includes fonts.

Class names and CSS variables use the `cui` prefix, and the package ships no global reset. Wrap your product content in `cui-root` where the scoped base rules help. Treat any override of library CSS as a deliberate exception worth reviewing.

## Upgrade

Your application stays on its installed version until you upgrade it.

1. Read the changelog and release notes for the version you are moving to.
2. Install its release archive. Build from the tag only when you need to reproduce it.
3. Install the exact filename, then review your dashboard, keyboard navigation and mobile layout.
4. Commit the archive, dependency and lockfile changes in one pull request.

To roll back, revert that commit and reinstall from the restored lockfile. Never point a production install at a moving `latest` URL.

## Charts

Charts sit behind a separate entry point so applications that skip them do not pay for Recharts.

To use them, install the peers and import from `@convert/product-ui/charts`:

```sh
pnpm add --save-exact recharts@3.10.1 react-is@19.2.8
```

Match `react-is` to your React version. See the Component guide for the chart recipes and their accessibility requirements.

## Report a bug or suggest a component

Open a [GitHub issue](https://github.com/tomrosscd/cd-product-ui/issues/new/choose) to report a bug or suggest a feature. You do not need to write code to suggest an improvement.

For code changes, follow [CONTRIBUTING.md](https://github.com/tomrosscd/cd-product-ui/blob/main/CONTRIBUTING.md). Merged improvements reach your application when you install a later version.
